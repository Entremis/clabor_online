# Клабор — счётчик очков

Приложение для игры вдвоём, втроём или пара на пару. Цель — 501 или 1001 очко. Один аккаунт объединяет компанию друзей: игроки, составы, текущая игра и история сохраняются в облаке и на устройстве, статистика рассчитывается из общей истории.

## Запуск и проверки

Нужен Node.js с поддержкой встроенного тестового раннера (проверено на Node.js 24). Dexie хранит данные в IndexedDB; fake-indexeddb используется только в тестах. Браузер загружает библиотеку из приложения, без внешнего CDN.

```sh
npm ci
npm start
```

Откройте `http://127.0.0.1:4177`. Для другого порта задайте переменную окружения `PORT`. Сервер доступен только на этом компьютере.

Для публикации на статическом HTTPS-хостинге выполните `npm run build` и используйте папку `dist`. Сборка включает все страницы, локальную библиотеку, иконки, манифест и версионированный офлайн-кэш. `npm run preview` показывает эту папку. Для локальной проверки офлайн откройте `/index.html?offline`; в обычной разработке новый service worker не регистрируется, но уже установленный продолжает обслуживать свой адрес. Для проверки свежего кода используйте отдельный порт либо обновите офлайн-версию.

На Vercel команда сборки и папка результата зафиксированы в `vercel.json`: `npm run build` → `dist`. Эта конфигурация переопределяет прежнюю настройку Output Directory `public` в проекте Vercel и применяется к Production и Preview.

```sh
npm test
```

## Принятые правила

- Игрок, выбравший масть, должен набрать больше каждого соперника. Если он набрал меньше максимума соперников — получает один бейт. Его очки этой раздачи переходят сопернику с наибольшим результатом. Остальные получают свои очки.
- На третьем и каждом последующем бейте дополнительно списываются 100 очков. Успешная игра не сбрасывает счётчик.
- **Нет взяток** обозначается вводом `-100` или кнопкой «Нет взяток (−100)». Это отличается от нуля очков: игроку списываются 100 очков. Штраф не передаётся сопернику. Если это одновременно третий или последующий бейт, общая сумма списания — **−100, не −200**; счётчик бейтов увеличивается как обычно.
- При равенстве выбравшего масть с максимальным результатом соперника возникает **висяк**. Очки всей раздачи откладываются; тот же игрок раздаёт и автоматически играет в выпавшую при раздаче масть. Приложение фиксирует, кто должен играть; физическая раздача определяет масть.
- Если следующая раздача успешна для этого игрока, всем начисляются свои очки за обе раздачи. Если она снова заканчивается висяком, перенос продолжается.
- Если висяк разрешился бейтом, выбравшему масть начисляется один бейт за разрешение ситуации. Его очки каждой отложенной раздачи получает лучший соперник именно в той раздаче; очки последней раздачи получает лучший соперник последней. Остальным начисляются все их собственные очки. Штраф −100 применяется один раз, если это третий или последующий бейт.
- Если два соперника имеют равный лучший результат при бейте, очки проигравшего переходят в отдельный банк ожидания. Их получит тот **из этих двух соперников**, кто наберёт больше очков в следующей раздаче. При повторном равенстве банк остаётся до следующей раздачи. Сравниваются набранные очки раздачи, а не общий счёт.
- Побеждает игрок с наибольшим общим счётом, достигшим цели. При одинаковом максимальном общем счёте на финише игра продолжается до разницы. Пример: 510:530 — победа второго; 510:510 — дополнительная раздача. Неразрешённые висяки и переходящие очки сначала должны быть разыграны.
- Банк раздачи и объявления используются только в парном режиме: 162 + терцы × 20 + полтинны × 50 + белла 20. Штраф за отсутствие взяток не входит в банк: при вводе −100 второй паре достаётся банк, например 162, а не 262. Индивидуальный режим принимает целые очки или −100 за отсутствие взяток без проверки на фиксированный банк.
- В парном режиме раздающий по-прежнему указан как команда. После висяка раздаёт играющий; после разрешения висяка очередь идёт к следующему за ним.

Подтверждённый пример: А играет; 60 / 60 / 42, затем 40 / 50 / 72. Итог — **0 / 170 / 154**, А получает один бейт (и −100, если это третий или последующий).

## Поведение приложения

- Профили игроков создаются один раз, затем выбираются для личных и парных игр. Есть избранное, переименование и архив. Один профиль нельзя занять дважды в одном составе. В каждой паре выбираются два человека.
- Состав сохраняет участников, пары, режим и цель. Реванш доступен после победы и в истории: те же участники и настройки, новая игра с нулевым счётом. Реванш из старой истории без профилей сохраняет подписи, не угадывая личности.
- Статистика завершённых игр показывает количество игр и побед, долю побед, средний итоговый счёт и бейты; есть фильтры по режиму и периоду, диаграмма побед и график итогов последних 20 игр. Командный результат учитывается у обоих участников и отдельно у пары независимо от порядка имён. Архивирование и переименование профиля сохраняют статистику.
- Доступны светлая, тёмная и системная темы. Выбор сохраняется на устройстве. Основное меню и переключатель темы находятся только на главной странице; остальные экраны содержат компактную ссылку возврата.
- После сообщения «Готово к игре без интернета» можно заново открывать все разделы и записывать игры без сети. Иконка на главном экране сама по себе этого не обеспечивает — теперь страницы и ресурсы кэшируются. Новая версия предлагается кнопкой обновления; данные хранятся отдельно от кэша приложения.

- Очки, выбор играющего и объявления текущего ввода сохраняются при каждом изменении. После успешной записи поля и объявления сбрасываются.
- Пустой, дробный ввод, отрицательные значения кроме −100 и раздача без играющего не записываются. В парном режиме сумма очков без штрафа за отсутствие взяток должна совпадать с банком. Для очков открывается цифровая клавиатура, штраф ставится кнопкой «Нет взяток (−100)» — в том числе при исправлении раздачи; количество объявлений вводится только неотрицательными числами.
- Редактируется вся раздача целиком. После сохранения пересчитываются все последующие раздачи, бейты, висяки, переходящие очки, раздающий и победитель. Незавершённое исправление тоже сохраняется как черновик. «Пересчитать игру» применяет открытое исправление с той же проверкой, что «Сохранить раздачу».
- Игроки с одинаковыми именами различаются по идентификаторам и получают номера в подписях. Имена выводятся текстом без интерпретации HTML.
- При изменении игры в другой вкладке старая вкладка блокирует запись и предлагает загрузить актуальную игру. Сохранение дополнительно сверяет исходную версию.
- Досрочно закрытая и пустая игра сохраняются без победителя. У игры, завершённой по правилам, победитель одинаков в табло и истории.
- Детальная таблица прокручивается внутри своей области, не расширяя страницу на телефоне. Диалоги подтверждения находятся на странице, поддерживают клавиатуру и отмену.

## Сохранения и совместимость

Основные данные находятся в IndexedDB (база `clabor`, таблица `kv`): `currentGame`, `gameHistory`, `playerLibrary`. При первом открытии исходные ключи localStorage переносятся одной транзакцией; оригиналы остаются нетронутыми как резервная копия, также сохраняется `__migrationBackup`. Отметка `__initialized` предотвращает повторный импорт старой игры после завершения или сброса. localStorage теперь используется только для предпочтения темы и исходной копии старых данных.

Новая модель активной игры имеет `version: 2`; игроки, профили и раздачи имеют постоянные ID. Прошлая история отображается по сохранённым результатам и не переписывается новым алгоритмом. Старые игры без связей с профилями не включаются в личную статистику: совпадения имён недостаточно для надёжного определения человека. Архивирование и запуск реванша атомарны. Версия данных проверяется внутри транзакции, изменения других вкладок сообщаются через BroadcastChannel.

При первом сохранении корректной старой активной игры она переводится в новый формат. Её исходная копия сохраняется в `claborBackupV1`, если такого ключа ещё нет. Очередь раздающего восстанавливается по раздачам, потому что прежний индекс сдвигался при показе страницы. Активная игра пересчитывается по правилам выше.

Старые объявления не были сохранены: приложение их не придумывает. При исправлении такой парной раздачи показывается пояснение о ручной проверке суммы. Старые раздачи без отметки играющего сохраняются с предупреждением в деталях; при исправлении нужно выбрать играющего. Структурно повреждённое сохранение, недопустимые очки или несколько играющих в старой раздаче не заменяются пустой игрой: выводится ошибка, исходные данные остаются нетронутыми.

В истории доступна разовая привязка подтверждённых старых имён к профилям. Она показывает, сколько игр добавит в статистику, не меняет счёт или раздачи и умеет отменяться. Нераспознанные имена и команды остаются в истории без статистики, пока для них не появится отдельное сопоставление.

При недоступности или переполнении хранилища показывается ошибка. Счёт не считается записанным до успешного сохранения. При ошибке архивации активная игра сохраняется; повторная попытка не дублирует запись истории.

При первом запуске создайте аккаунт компании по логину и паролю. Друзья входят с теми же данными; другая компания создаёт свой аккаунт. Перенос прежних локальных сохранений предлагается при входе, а также в разделе «Аккаунт», если его пропустили. Перенос выполняется один раз, исходная копия остаётся на устройстве.

После первого входа можно играть без интернета. Изменения отправляются при восстановлении связи и открытии приложения; открытый экран получает обновления каждые 30 секунд. Кнопка «Синхронизировать» запускает обмен сразу. При разных правках одной записи раздел «Аккаунт» предлагает выбрать вариант, сохранив обе версии в локальной резервной копии. Выход сохраняет неотправленные изменения отдельно для прежнего аккаунта. Очистка данных сайта удаляет именно локальные, в том числе ещё не отправленные, записи.

Подключение, локальная разработка и устройство сервера описаны в [CLOUD_PLAN.md](CLOUD_PLAN.md). Восстановление забытого пароля через почту пока не реализовано.

Из первоначальных предложений ещё остаются: экспорт/импорт резервной копии, отмена последней раздачи, личные встречи, настраиваемые домашние правила, карточка результата для друзей, несколько отложенных игр и турнирный режим.

## Устройство проекта

- `game_engine.js` — модель, проверка данных, миграция и независимый расчёт правил.
- `game_store.js`, `database.js` — операции сохранения и транзакции IndexedDB, миграция, защита от устаревшей записи.
- `player_library.js`, `players.js` — профили, составы, реванш и вычисление статистики.
- `statistics.js` — таблицы статистики, фильтры и графики.
- `app_shell.js`, `sw.js`, `build.cjs` — навигация, темы, офлайн-режим и сборка.
- `game_logic.js` — экран игры и редактор раздач.
- `setup.js`, `history.js` — настройка и история.
- `confirmation.js` — доступное подтверждение действий.
- `account.html`, `account.js`, `cloud_client.js` — вход, перенос сохранений, обмен данными и разрешение конфликтов.
- `sync_model.js`, `cloud-worker/` — изменения отдельных записей, серверные версии, авторизация и D1.
- `tests/cloud.test.cjs` — два клиента, разделение аккаунтов, перенос, повтор запросов, конфликты и постраничная загрузка.
- `tests/game.test.cjs` — проверки правил, сохранения и сохранения суммы очков с учётом отложенных начислений и штрафов.
- `tests/players.test.cjs`, `tests/database.test.cjs` — профили, статистика, реванш, перенос данных и конкурентная запись.
